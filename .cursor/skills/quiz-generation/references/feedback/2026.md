## 2026-07-18-01: 多オブジェクト機能は対象オブジェクトを明示する

- Quiz: 2026-07-20 / CREATE OR ALTER TABLEの宣言的DDL
- Source: user-feedback
- Phase: review
- Signal: CREATE OR ALTER を総称で出題したが、列リネーム等の論点は TABLE 固有。レビューで対象オブジェクトの明示を求められ修正した
- Cause: 機能ファミリー名で書いてしまい、問題が依拠するオブジェクト境界が曖昧になった
- Action: タイトル・問題文・選択肢・解説を CREATE OR ALTER TABLE に絞った。次回も多オブジェクト対応機能は、論点が依拠するオブジェクトを問題文で先に固定する
- Success metric: 同様の総称機能（CREATE OR ALTER / ALTER 系など）で、レビュー前に対象オブジェクトがタイトルまたは問題文に明示されている
- Tags: `出題範囲`, `オブジェクト明示`, `Snowflake`
- Status: candidate
- Related: none

## 2026-07-25-01: authorのモデル名は推測しない

- Quiz: 2026-07-27〜08-02 / 来週分一括作成
- Source: user-feedback
- Phase: authoring
- Signal: author に `jimatomo with Fable` と入れたが、実際に使っていたモデル表記は Composer。レビュー後に全問修正した
- Cause: モデル名が不明なときに確認せず推測で記入した。SKILL には「分からない場合は確認」とあるが、推測禁止が明示されていなかった
- Action: feedback に記録し、SKILL の author 手順を「推測禁止・不明時は確認必須」に補強した
- Success metric: 次回以降、author のモデル名がレビュー前に正しい表記で入り、推測由来の修正が起きない
- Tags: `author`, `モデル名`, `推測禁止`
- Status: adopted
- Related: none
